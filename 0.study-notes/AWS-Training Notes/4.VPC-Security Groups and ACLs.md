**Security Group

Virtual firewall for an Instance
	Assigned to vNIC of instance by you
	 Applies only to instances assigned to
	 Every EC2 needs Security Group
	 Same as RDS instance, needs sec. group
	 same as Load Balancer
Allows to control inboud and outbound traffic. 
	"Allow" rules only- if not in sec.group, access gets denied. 
	
Can use multiple sec groups to a single instance instance.
-Sec.Groups are stateful:
	if inbound is only via SSH
	 Return traffic is automatically allowed. 
You can build SGs in VPC, RDS, or EC2 consoles. 
	All of them are the same 

Existing Security Groups can applied in NEW security group as Source, where Source will pull your existing security groups. 
	i.e. you can create a custom sg outbound on port 3306 for App server, then you can use the same SG for DB server as inboung SG on port 3306. 
You can specify inboung SG. 
-But for Outbound you need an IP. 


**ACL (Acess Control List)

Are **statesless**; return traffic is not automatically allowed
Has numbering scheme, lowest to highest number=top down processing
	i.e. Rule 100 is processed before 101 or 102. 
ACL goes/applies to your **subnets**

ACL is top-down processing. Make sure to include your DENY access rules first. 

To allow the traffic outbound, you have to create a ACL rule. 
	Not all **Outbound** traffic can be allowed= NOT secure enough. 
	 You have to be specific with ports, use Ephemeral Ports on aws Documentation. 
		 usually it is 1024-65535 custom TCP traffic. 
You have to carefully craft the **Inbound** and according/corresponding **Outbound** rules.
