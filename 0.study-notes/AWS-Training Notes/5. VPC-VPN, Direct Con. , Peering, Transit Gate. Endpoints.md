**VPC Peering**
Connection between two different VPCs
Private IPv4 or IPv6 adressing
VPCs can be in different accounts
	Connect your VPC to customer (who use AWS) VPC to start exchange of info. 

Adress spaces must not overlap
Non-Transitive
	If VPC A & B have Peering Connection, and VPC A has Peering Connection with VPC C, THEN VPC B does NOT have connection to VPC C, via VPC A. 
     VPC A -> VPC B
    |_ > VPC C
	If you want VPC b and C to talk, you need to connect them. 

**VPC Endpoint**

If your resources outside of VPC, but in the same region, want to talk to your resources within VPC, you need to set up ENDPOINTS

Without VPC Endpoint-traffic leaves AWS network to access S3, THEN Public IPs, IG, or. NAT required

WITH VPC Endpoint- traffic stays within AWS network to access S3, NO Public IPs, NAT or IG.

VPC endpoint Improves performance and Security. 

**Interface vs Gateway Endpoint**

Traffic does not leave the AWS network when communicating with services = ANSWER is Endpoints. 

**Interface** Endpoint (powered by AWS privatelink)
Services Include: AMZ API Gateway, AMZ CloudWatvh Logs, AWS CodeBuild, EC2 API, KMS, Elastic Load Balance, Enpoint Services hosted by other AWS accounts, AWS Marketplace partner services

**Gateway** Endpint services: S3, and DynamoDB
