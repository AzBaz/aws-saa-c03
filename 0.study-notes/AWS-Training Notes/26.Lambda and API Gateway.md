 [[0. AWS-SAA-Training Overview]]  [[25.Introducing the Serverless Architecture]]

**AWS Lambda**- Serverless Computing; No servers to manage, monitor or maintain. 
Scales continuously for you based on demand; No capacity planning. 
Ver cheap compared to all other options. 

You can run code without provisioning or managing servers and/or containers
	Based on event it can trigger- Changes to S3 bicker, OR Changes to Dynamo DB table. 
	Based on requests- HTTP/HTTPS OR API calls from AWS SDKs. 
**Lambda Supported. Languages**: Python, NodeJS, Ruby, C#, Go, Java, PowerShell

**Lambda Concurrency**- Number of requests that your function is serving at any given time. 
This improves throughput
Up to a soft **limit of 1000 requests** per region for all functions combined (Account concurrency limit). Lambda will scale out the number of connections until the max is reached. 
	AWS support can change the soft limit of 1,000, it you need more. 
Types: 
	Standard
	Reserved (is the max. number of concurr. connections per func.)- Popular or well used connections get reserved, so that they do not throttle. Once reserved, no other app can use the reserved conrurr. connections. 
	Provisioned- Helps to speed up the execution process, every time lambda f(x) is triggered.

**Lambda ans VPC**- By default Lambda function itself always runs inside a VPC owned by the Lambda service.
No access between your Lambda function and your resources in your VPC. VPCs canNOT talk to each other by default. 
*Enable VPC in Lambda Function*- Create a Hyperlane ENI
Hyperlane ENIs provide NAT capabilities from the Lambda VPC to your account VPC, using VPC-to-VPC NAT (V2N) but not in the other direction. 
Use a VPC interface Endpoint to connect the VPC to lambda. 

**API Gateway**- AWS Service that enables developers to create, publis, maintain, monitor, and secure APIs
	To access private/public AWS services, other web services, and data stored in the cloud.
	Uses RESTful APIs

*API* - Triggers the lambda function based on user's API request type (GET, POST, PUT DELETE); Entry point for API's; Receiving requests and sending responses.
