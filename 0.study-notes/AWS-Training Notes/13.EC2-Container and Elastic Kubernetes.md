**Containers**- A method of operating system virtualization that allow you to run an application and its dependencies in resource-isolated process 
![[Pasted image 20260609153628.png]]

Each VM has an app with all settings and etc. BUT we can put that app with all bells and whistles into a container. 

![[Pasted image 20260609153715.png]]

Deploy containers at application layer. (can be deployed in web tier as well.)

If you building many apps and containerizing them, it is easy to  loose track of containers. Hard to track performance and each container. 

**Amazon ECS**- Elastic Container Service, that allows to monitor the containers.
	Supports Docker. Mainly works with Docker.
	Highly scalable and high performing, secure and reliable.
	Run on Cluster of EC2 instances
		You manage servers.
**Amazon ECR**- Elastic Container Registry, this is where you build images, and store using ECR or any other repository.
	Build and store you images for Docker.

You can deploy your containerized app on AWS Fargate, AWS Regions, AWS Local Zones, AWS Wavelength, AWS Outposts, ECS anywhere. 
	You can manage all your containers from ECS console. 

--NOT heavily tested on ECS on exam. 

Run the containers on **AWS Fargate**- manages the containers for. (see comparison with running containers on Cluster with EC2)
	Run containers without servers or clusters
	No servers to manage (there are servers and clusters behind the scenes BUT you are not responsible for them)

**Amazon EKS**- Elastic Kubernetes Service, container management service. 
	Run on Cluster of EC2 servers
		You manage servers.
	Highly Scalable
	High Performance

**AWS Fargate**- AWS managed service for the containers
Pricing:
	On Demand- based on your usage
	Spot Pricing- Use only if your app is interrupt-tolerant
		Up to 70% cheaper than on-demand
	Compute Savings Plan- Use if you have a consistent amount of Fargate usage
		Up to 50% cheaper than On-Demand.
