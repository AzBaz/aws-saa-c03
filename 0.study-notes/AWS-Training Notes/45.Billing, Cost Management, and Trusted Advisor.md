*4 Best Practices of Cost Optimization*
- Cost-effective resources- Use appropriate instances and resources. Use managed services
- Matching Supply Demand- Do not over provision instances and resources. Deliver the lowest cost for a system over time. Use Managed services (i.e. DynamoDB better than SQL DB, when you don't really need relational DB)
- Expenditure Awareness - Keep informed about expenses. Monitor expenses on a regular basis.
- Optimize over time - Review existing architecture, and determine of new or updated services can reduce costs. 
	- Identify any resources that can be de-commisioned. Use managed services (RDS vs. Instance with DB)

**AWS Billing and Cost Management** - AWS Cost Explorer, visualize and analyze cost/usage over time (up to 12 months history, 12 months forecast). Filter by service, tag, account, region. Good for spotting trends and RI/Savings Plan recommendations.

- AWS **Cost & Usage Report (CUR)**, the most granular billing data available. Delivered to S3, hourly/daily line items. Query with Athena/Redshift/QuickSight. Use when you need deep, detailed analysis.
- Cost Allocation Tags, tag resources to break down costs by project/team/env. Two types: AWS-generated (prefix `aws:`) and user-defined (prefix `user:`). Must be activated in the billing console before they appear in reports.

*Budgeting & alerts* (exam heavy)
- AWS Budgets, set custom budgets for cost, usage, RI/Savings Plan coverage/utilization. Triggers alerts (SNS/email) when thresholds are forecast or actually breached. Can trigger automated actions (e.g., apply IAM policy, stop instances).
- AWS Cost Anomaly Detection, ML-based; detects unusual spend and alerts you. Free.
- Billing Alarms via CloudWatch, older method; metric only in us-east-1. Budgets is the preferred/modern answer.

*Cost optimization tools*
- Compute Optimizer, ML recommendations to rightsize EC2, EBS, Lambda, ECS/Fargate based on usage. Reduces over-provisioning.
- Savings Plans, flexible commitment (1 or 3 yr) for a $/hour compute spend. Cheaper than On-Demand. Types: Compute (most flexible, any region/family/instance), EC2 Instance (specific family+region, biggest discount), SageMaker.
- Reserved Instances (RIs), commitment to specific instance config for discount. Less flexible than Savings Plans.

*Consolidated billing* (from Organizations, appears here too)
- One bill for all accounts; volume tier discounts and RI/Savings Plan sharing applied across the org.
*Exam traps*
- "Most detailed / granular billing data" = CUR (not Cost Explorer).
- "Visualize and forecast spend quickly" = Cost Explorer.
- "Alert before/when spend exceeds threshold" = Budgets.
- "Detect unexpected/unusual charges automatically" = Cost Anomaly Detection.
- Cost allocation tags must be activated to work.

**AWS Trusted Advisor** - Inspects your AWS environment and makes recommendations based on Best Practices obtained from aggregated operational history of AWS customers. 


***Five check categories (memorize these)***
- *Cost Optimization*, idle/underutilized resources, unused RIs, low-usage instances.
- *Performance*, over-utilized resources, service limit issues, config improvements.
- *Security*, open security groups, S3 bucket permissions, MFA on root, IAM use, exposed keys.
- *Fault Tolerance*, Multi-AZ, backups, redundancy, health checks.
- *Service Limits* (Service Quotas), usage approaching account limits.

***Support plan tiers (exam distinction)***
- Basic / Developer plans: only a limited set of checks (core security checks + all service limit checks).
- Business / Enterprise plans: all checks in every category, plus programmatic access via API and CloudWatch/EventBridge integration for automated alerts.

***Exam traps***
- Full Trusted Advisor checks require Business or Enterprise Support (not Basic).
- "Automated best-practice recommendations across security, cost, performance, fault tolerance, service limits" = Trusted Advisor.
- Do not confuse with AWS Config (compliance/config rules), Compute Optimizer (rightsizing only), or Security Hub (security posture aggregation).
