**Elastic Load Balancers (ELB)**
Can be used for EC2, and other services as well. 
	On exam, primarily will be tested on EC2 behind the ELB

ELB- Automatically distribute traffic among multiple EC2 instances OR other services.
	Increase the availability of your applications and services. 

*ELB Characteristics*
-Single point of contact for incoming requests
	Instead of hitting server directly you hit a load balancer
-Distributes incoming traffic to multiple EC2 instances
	Based on the health of the instances
	Within single or multiple AZs
	Within public or private subnets
-Increases fault-tolerance of applications improving availability
-Scales automatically based on traffic demand
	Managed automatically by AWS.


**HOW ELB Works?**
**Lead Balancers:** 4 types: Application, Network, Gateway, and Classic Load Balancers. 
***App Load Balance*r**- User Auth, Rich Metrics/Logging, Redirects, Fixed/Response
	Source: HTTP/HTTPS, HTTP 1.1/HTTP/2, gRPC, websocket
	Targets: EC2, Lambda, Fargate, EKS, ECS.
***Network Load Balancer***- Layer 4 TCP/UDP Connection Based, Source IP preservation, Low Latency. 
If scenarios is NOT about hhtp/https, THEN always PICK Network Load balancer. 
	Source: Static IP, Elastic IP, AWS PrivateLink
	Targets: EC2 auto scaling groups, Fargate, EKS, ECS, IP address, App. Load Balancer.
	You can also put Layer 7 Web App. Firewall (WAF), AWS Certificate Manager, Cognito. 
***Gateway Load Balancer***=Security Appliances; Health Checks; 
	Source: Internet, Ingress Routing/Route tables.
