# AWS SAA-C03 Exam Topics, Consolidated From Past Sessions

Compiled from your study chats: EBS/IOPS, Lake Formation, VPC design, Prometheus/Grafana, EventBridge and AI/ML notes, CloudTrail/SSM/Storage Gateway, and EKS autoscaling.

## Storage

| Service/Topic | What It Does | Exam Watch-Outs | Common Traps |
|---|---|---|---|
| EBS io1/io2 | Provisioned IOPS SSD for latency-sensitive, transactional workloads | Max IOPS = volume size (GiB) x 50. Shortcut: multiply by 100, halve | Confusing the x50 ratio with x100; picking high queue length for SSD (SSD wants low queue length, HDD wants high) |
| gp2/gp3 vs st1/sc1 | General purpose SSD vs throughput HDD (st1) vs cold HDD (sc1) | st1/sc1 are for sequential, throughput-heavy workloads, never boot volumes for sc1 | Choosing st1/sc1 for random I/O or transactional workloads |
| S3 Storage Classes | Standard, IA, One Zone-IA, Glacier tiers, Intelligent-Tiering | Lifecycle policies for automatic transitions; retrieval time tradeoffs for Glacier tiers | Picking Glacier for frequently accessed data; forgetting minimum storage duration charges |
| Storage Gateway | Hybrid on-prem to S3 bridge | File Gateway = NFS/SMB to S3; Volume Gateway = iSCSI block (cached vs stored mode); Tape Gateway = virtual tape library | Confusing cached mode (primary data in S3, local cache) with stored mode (primary data on-prem, async backup to S3) |

## Networking

| Service/Topic                                    | What It Does                                                                                                                 | Exam Watch-Outs                                                                            | Common Traps                                                                                                   |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| VPC Subnet Design                                | Multi-tier, multi-AZ subnet layout                                                                                           | Subnet count = number of tiers x number of AZs for HA requirements                         | Undercounting subnets by ignoring the AZ multiplier (e.g., answering 3 instead of 6)                           |
| VPC Endpoints                                    | Private connectivity to AWS services without internet                                                                        | Gateway endpoints (S3, DynamoDB) are free; Interface endpoints (PrivateLink) cost per hour | Using an Interface endpoint where a free Gateway endpoint would work                                           |
| Prefix Lists + AWS RAM                           | Customer-managed prefix lists shared across accounts via Resource Access Manager                                             | Centralizes and simplifies security group/route table management across an org             | Overcomplicating with Firewall Manager or Security Hub automation when RAM + prefix lists is the leaner answer |
| Network ACLs vs Security Groups vs WAF           | NACL = stateless, subnet-level; SG = stateful, instance-level; WAF Web ACL = Layer 7 filtering on ALB/CloudFront/API Gateway | NACLs process rules in number order and need explicit allow/deny both directions           | Confusing Network ACLs with WAF Web ACLs, they are unrelated despite the name overlap                          |
| ELB Family (ALB/NLB/GWLB)                        | ALB = Layer 7 HTTP/HTTPS; NLB = Layer 4 ultra-low latency; GWLB = transparent traffic inspection                             | All are regional, soft limit ~50 load balancers per region                                 | Picking ALB for non-HTTP TCP/UDP workloads that need NLB                                                       |
| Site-to-Site VPN vs Client VPN vs Direct Connect | S2S VPN = network-to-network over internet; Client VPN = individual user access; Direct Connect = dedicated private line     | Direct Connect + VPN hybrid gives encrypted backup over the dedicated line                 | Assuming Direct Connect alone is encrypted, it is not, add VPN for encryption                                  |
| Virtual Private Gateway + Transit Gateway ECMP   | Equal Cost Multipath routing aggregates VPN bandwidth across multiple tunnels                                                | ECMP requires BGP (dynamic routing), not static routing                                    | Trying to use ECMP with static VPN routing, it will not aggregate bandwidth                                    |
| Route 53 Multivalue Answer                       | Returns up to 8 healthy IPs per DNS query with health checks                                                                 | Not a true load balancer, just DNS-level basic distribution with health awareness          | Confusing it with simple round robin (no health checks) or an actual load balancer                             |
| Route 53 Failover/Health Checks                  | DNS-level failover and RTO/RPO strategy                                                                                      | Combine with RDS/S3 cross-region replication for full resilience scenarios                 | Treating Route 53 as sufficient for intra-region distribution, that is what regional load balancers are for    |

## Security

| Service/Topic | What It Does | Exam Watch-Outs | Common Traps |
|---|---|---|---|
| IAM Policies | Identity and access control, least privilege | Cannot enforce column-level or row-level filtering inside a dataset | Choosing IAM policy as the answer for column-level access control (needs Lake Formation) |
| Lake Formation | Centralized data lake governance | Data filters enable column-level and row-level access control; blueprints automate ingestion (e.g., Aurora to S3) | Picking Glue Studio + IAM policies instead of Lake Formation data filters for column-level control |
| KMS | Encryption key management, at rest and in transit | Know CMK vs AWS-managed keys, envelope encryption basics | Overlooking that CloudTrail logs default to S3-managed encryption unless KMS is specified |
| GuardDuty | Managed threat detection using ML and threat intel feeds | Agentless, continuously monitors account activity | Confusing with Security Hub (aggregator) or Inspector (vulnerability scanning) |
| CloudTrail vs CloudWatch | CloudTrail = API call auditing/history; CloudWatch = metrics, logs, alarms | CloudTrail answers "who did what," CloudWatch answers "how is it performing" | Using CloudWatch when the scenario needs an audit trail of API calls |
| Systems Manager (Session Manager) | Secure shell access without bastion hosts or open SSH ports | Requires SSM Agent and an IAM role with the right managed policy | Picking a bastion host solution when Session Manager removes the need for one entirely |
| AWS Organizations / Control Tower | Multi-account governance and guardrails | Control Tower builds on Organizations with automated landing zone setup | Confusing Organizations (the account structure) with Control Tower (the automation layer on top) |

## Resilience

| Service/Topic | What It Does | Exam Watch-Outs | Common Traps |
|---|---|---|---|
| Multi-AZ vs Cross-Region Replication | Multi-AZ = HA within a region; cross-region = DR across regions | Map RTO/RPO requirements to the right pattern | Choosing cross-region replication when the requirement is same-region HA, over-engineering the answer |
| RDS/S3 Failover Behaviors | Automatic failover to standby (RDS Multi-AZ), cross-region replication (S3 CRR) | Multi-AZ standby is not readable, that is what read replicas are for | Confusing Multi-AZ (failover only) with read replicas (scaling reads) |

## Data, Analytics, and Integration

| Service/Topic | What It Does | Exam Watch-Outs | Common Traps |
|---|---|---|---|
| Athena | Serverless SQL queries directly on S3 data | Columnar formats like Parquet cut cost and scan time significantly | Using row-based CSV/JSON at scale instead of Parquet, driving up query cost |
| QuickSight | BI dashboards and visualization | Often paired with Athena as the query layer underneath | Choosing QuickSight to also handle the query/transform layer, that is Athena/Glue's job |
| Glue | Serverless ETL, data cataloging | Glue Studio is for visual ETL jobs, not for access control | Using Glue for security/access control scenarios, it is a data processing tool |
| AppFlow | Managed data integration between SaaS apps and AWS | Use for SaaS-to-S3/Redshift flows without custom code | Overengineering with Lambda/Glue when AppFlow is a native no-code fit |
| Kinesis Data Streams | Real-time data streaming and ingestion | Default retention 24 hours, extendable up to 365 days | Assuming default retention is long-term storage, it is not, S3 is the long-term destination |
| EventBridge | Event bus for decoupled, event-driven architectures | Supports SaaS partner event sources and scheduled rules | Confusing with SNS/SQS, EventBridge is for routing structured events by pattern, not simple pub/sub or queuing |

## AI/ML Services

| Service | What It Does | Exam Watch-Outs |
|---|---|---|
| Translate | Language translation | Managed, no model training required |
| Transcribe | Speech to text | Look for audio/call-center scenarios |
| Textract | Extracts text and data from scanned documents/forms | Distinguish from Comprehend, which analyzes text meaning, not extraction |
| Comprehend | NLP, sentiment and entity analysis on text | Works on text already extracted, pairs with Textract in pipelines |
| Rekognition | Image and video analysis | Facial recognition, object detection scenarios |

## Compute and Containers

| Service/Topic | What It Does | Exam Watch-Outs | Common Traps |
|---|---|---|---|
| EKS Autoscaling and Nodes | Managed Kubernetes with Cluster Autoscaler/Karpenter and managed node groups | Know the difference between pod-level (HPA) and node-level (Cluster Autoscaler) scaling | Assuming EKS autoscaling is identical to EC2 Auto Scaling Groups, the trigger logic differs |
| EMR / EKS / Batch | Big data processing vs container orchestration vs batch job scheduling | Match the workload pattern (Spark/Hadoop, containers, batch jobs) to the right service | Picking EMR for simple containerized workloads, or Batch for interactive querying |
| Elastic Beanstalk | PaaS for deploying and managing web apps | You upload code, Beanstalk handles provisioning, load balancing, scaling | Assuming full infrastructure control, Beanstalk abstracts most of it away by design |

## Monitoring and Observability

| Service/Topic | What It Does | Exam Watch-Outs | Common Traps |
|---|---|---|---|
| Amazon Managed Prometheus | Collects and stores Prometheus-format metrics | Trigger is the metrics format, not that it is ECS-specific | Assuming it is tied only to ECS/EKS, it works with any Prometheus-instrumented source |
| Amazon Managed Grafana | Multi-source unified dashboarding | Trigger is needing dashboards pulling from multiple data sources | Picking Grafana when the actual need is metrics collection (that is Prometheus's job) |
| Sticky Sessions vs External Session Store | ALB sticky sessions bind a user to one target; ElastiCache/DynamoDB decouple session state | Decoupled stores are preferred for scalability and stateless architecture | Using sticky sessions as a long-term architecture pattern instead of a stateless session store |

## Cost Optimization

| Topic | What It Does | Exam Watch-Outs |
|---|---|---|
| Reserved Instances vs Savings Plans vs Spot | Different commitment/discount models for EC2 | RIs are capacity-specific, Savings Plans are flexible, Spot is interruptible and cheapest |
| S3 Lifecycle Policies | Automates storage class transitions and expiration | Match access patterns to the right transition schedule |
| Trusted Advisor | Automated recommendations across cost, security, performance, fault tolerance | Some checks require Business/Enterprise support plan |
| Resource Groups | Logical grouping of resources for management and cost tracking | Not a cost tool by itself, works alongside Cost Explorer/Billing |
