#  Part 1 — Flashcards

## Topic A — Security Groups vs Network ACLs

Are Security Groups stateful or stateless?
?
**Stateful.** Return traffic is automatically allowed — you only write the request-direction rule.
<!--SR:!2026-08-24,8,250-->

Are Network ACLs stateful or stateless?
?
**Stateless.** Return traffic is NOT tracked — you must open **both** an inbound *and* a matching outbound rule.
<!--SR:!2026-08-18,2,230-->

Which can write an explicit DENY rule: Security Group or NACL?
?
**Only the NACL.** Security Groups are allow-only. If a question says "explicitly block / deny," the answer involves a NACL.
<!--SR:!2026-08-17,1,178-->

What does a Security Group attach to vs a NACL?
?
**Security Group → the ENI/instance.** **NACL → the entire subnet.**
<!--SR:!2026-08-17,1,210-->

Can a Security Group rule reference another Security Group as its source?
?
**Yes.** e.g. allow the ALB's SG (or a bastion's SG) as the source instead of hard-coding an IP. This is the correct fix when an upstream IP changes.
<!--SR:!2026-08-20,11,270-->

An SSH connection reaches the bastion host but times out connecting from the bastion to a private instance. Where is the block, and what's the fix?
?
The block is the **private instance's Security Group**. Fix: add an inbound rule allowing the **bastion's security group** as the source (port 22).
<!--SR:!2026-08-18,2,230-->

You must explicitly block inbound HTTP (port 80) to an instance. SG or NACL?
?
**NACL** — modify the subnet's NACL to deny TCP 80. Security Groups cannot deny.
<!--SR:!2026-08-18,2,250-->

A custom NACL only has an outbound "allow HTTP" rule. Does inbound HTTP work?
?
**No.** NACLs are stateless; you also need an explicit **inbound** allow rule for return/request traffic to work.
<!--SR:!2026-08-17,1,178-->

Web tier initiates connections to the DB tier on 1433. Which SG rules? (state direction for each)
?
**DB SG: inbound** 1433 from the web SG. **Web SG: outbound** 1433 to the DB SG. (The initiator needs outbound; the receiver needs inbound. Stateful = no return rules needed.)
<!--SR:!2026-08-18,2,230-->

An ALB's public IP keeps changing and breaking the EC2 security-group rule. Correct long-term fix?
?
Reference the **ALB's security group** as the source in the EC2 SG (not the IP, not a CloudWatch watcher).
<!--SR:!2026-08-17,1,210-->

## Topic B — RDS: Read Replica vs Multi-AZ

What is a Read Replica for, and can it take writes?
?
**Read-only** performance/scaling. It **cannot** take writes. Can span AZs *and* regions.
<!--SR:!2026-08-24,8,250-->

What is Multi-AZ for? Can you read or write the standby?
?
**Availability/failover only.** The standby serves **no reads and no writes** — it's not a performance feature.
<!--SR:!2026-08-18,2,198-->

Read-heavy workload needs offloading but you can't add another RDS instance. What do you use?
?
**ElastiCache (Memcached or Redis)** to cache the recurrent reads.
<!--SR:!2026-08-17,1,210-->

Does a cross-region Read Replica share the source's KMS key?
?
**No.** Each region uses its own region-specific KMS key.
<!--SR:!2026-08-20,4,198-->

Does Multi-AZ improve database performance?
?
**No** — availability only. Choosing it for a "performance / burst reads" requirement is wrong.
<!--SR:!2026-08-23,7,250-->

Which RDS engine suspends I/O on the *primary* during automated backups (so avoid it for latency-sensitive OLTP)?
?
**SQL Server.** Other engines take backups from the standby, so the primary is unaffected.
<!--SR:!2026-08-20,4,218-->

Does RDS for SQL Server 2014 support read replicas?
?
**No.** For a read bottleneck on SQL Server 2014, cache with **Memcached** instead.
<!--SR:!2026-08-27,11,270-->

## Topic C — Backups & Snapshot Survivability

When you delete an RDS instance, what happens to automated snapshots?
?
They are **deleted with the instance.** Only **manual snapshots** and a **final snapshot** (if enabled at delete) survive.
<!--SR:!2026-08-20,4,210-->

What single setting prevents accidental RDS instance deletion?
?
**Deletion protection** (enabled by default for production DBs created via console).
<!--SR:!2026-08-23,7,250-->

Does creating a scheduled AMI back up an EFS file system?
?
**No.** An AMI backs up **EBS** only. For EFS use **AWS Backup** or an EFS-to-EFS backup solution.
<!--SR:!2026-08-17,1,210-->

What's the managed answer for FSx cross-region DR with a defined RPO?
?
**AWS Backup** — scheduled backups at the RPO interval with automatic cross-region copy (encrypted by default). DataSync on an hourly task can't meet a 30-min RPO.
<!--SR:!2026-08-17,1,210-->

Is EBS billed when the instance is stopped or terminated?
?
The **EBS volume keeps billing** (provisioned GB) until the *volume* is deleted. Compute stops billing when stopped.
<!--SR:!2026-08-26,10,218-->

Can you use EC2 Instance Store for backups?
?
**Never.** Instance Store is ephemeral. Use S3 Standard/IA for backups needing quick restore (RTO/RPO).
<!--SR:!2026-08-20,4,198-->

How do you resize a Linux EBS volume that's almost full, short-term?
?
**Resize it live** while the instance runs — no stop, no detach, no snapshot needed.
<!--SR:!2026-08-18,2,230-->

#  Part 2 — Practice Questions: Security Groups vs NACLs

Answer each, then check the collapsed answer. Exam-style; some are "Select TWO."

### Q1
A web server in a public subnet must be reachable on HTTPS (443) from the internet, and you also need to **explicitly block** a specific malicious IP range. Which combination is correct? (Select TWO.)

- A. Add an inbound allow rule for 443 in the security group
- B. Add an inbound deny rule for the malicious range in the security group
- C. Add an inbound deny rule for the malicious range in the subnet's NACL
- D. Add an outbound deny rule for the malicious range in the security group

> [!success]- Answer
> **A and C.** Security groups allow 443 (allow-only), and only a **NACL** can *deny* the malicious range. B and D are impossible — SGs have no deny.

### Q2
Instances in a private subnet can't receive replies to their outbound HTTP requests. The subnet uses a **custom** NACL with only an outbound "allow TCP 80" rule. What's missing?

> [!success]- Answer
> An **inbound** NACL rule allowing the return traffic (ephemeral ports 1024–65535, or the needed inbound allow). NACLs are **stateless**, so return traffic is not automatic.

### Q3
A three-tier app: ALB → EC2 web tier → RDS. You want the web tier to accept traffic **only** from the ALB, without hard-coding IPs. What do you configure?

> [!success]- Answer
> In the **web-tier security group**, add an inbound rule with the **ALB's security group** as the source. Referencing the SG survives ALB IP changes.

### Q4
True or false: A network ACL rule change takes effect only after you reboot the instances in the subnet.

> [!success]- Answer
> **False.** NACL (and SG) changes apply immediately, no reboot.

### Q5
A DB tier (RDS SQL Server, port 1433) in a private subnet must accept connections **only** from the web tier and send replies. No other traffic allowed. Which rules? (Select TWO.)

> [!success]- Answer
> **DB SG inbound: allow 1433 from the web-tier SG.** **Web SG outbound: allow 1433 to the DB-tier SG.** Because SGs are stateful, no return rules are needed. (Inbound 1433 from 0.0.0.0/0 or "web inbound from DB" are wrong — wrong direction/scope.)

### Q6
You want to block all traffic from an entire country/CIDR range to every instance in a subnet, regardless of each instance's own rules. Best tool?

> [!success]- Answer
> **NACL** on the subnet (deny the CIDR). It applies subnet-wide and can deny; a security group can't deny and only applies to attached instances.

### Q7
Which statements are TRUE? (Select TWO.)

- A. Security groups are evaluated before NACLs for inbound traffic
- B. NACLs are evaluated before security groups for inbound traffic
- C. Security groups can be attached to individual instances
- D. NACLs can be attached to individual instances

> [!success]- Answer
> **B and C.** For **inbound** traffic the packet hits the **subnet NACL first**, then the instance's SG. NACLs attach to subnets only; SGs attach to instances.

### Q8
An instance can make outbound connections but no one can reach it inbound, even though its security group allows the port. The subnet's custom NACL allows the inbound port but has no matching outbound rule. Why does it fail?

> [!success]- Answer
> The **NACL is stateless** — the *response* leaves on an **ephemeral port** that the outbound NACL rules must allow. Missing outbound ephemeral-port allow = replies dropped.

### Q9
Default behavior check: What does the **default** NACL allow, and what does a **newly created custom** NACL allow?

> [!success]- Answer
> **Default NACL:** allows **all** inbound and outbound. **Custom NACL:** **denies all** inbound and outbound until you add rules.

### Q10
You need a bastion host in a public subnet to SSH into instances in a private subnet. SSH to the bastion works; SSH from bastion to a private instance times out. Most likely fix?

> [!success]- Answer
> Add an **inbound rule on the private instance's security group** allowing **port 22 from the bastion's security group**. (A connection *timeout* points to a security-group/firewall block, not routing.)

### Q11
Rank how these process an inbound packet destined for an EC2 instance, from first to last: Security Group, Route Table, Network ACL.

> [!success]- Answer
> **Route Table → NACL (subnet) → Security Group (instance).** Routing gets the packet to the subnet, the NACL filters at the subnet edge, then the SG filters at the instance.

### Q12
Which of these can you do with a security group but NOT a NACL? (Select TWO.)

- A. Reference another security group as a source/destination
- B. Write an explicit deny rule
- C. Rely on stateful return-traffic handling
- D. Apply the rule set to an entire subnet at once

> [!success]- Answer
> **A and C.** Referencing another SG and stateful behavior are SG-only. Deny rules (B) and subnet-wide application (D) are NACL features.

#  Part 3 — Flashcards: PT-2 Weak Areas

## Topic D — Storage Type Selection

Which EBS volume type is cheapest for a large data warehouse, and what can't it do?
?
**st1 (Throughput Optimized HDD)** — cheap, built for large sequential/warehouse workloads. HDD types (st1/sc1) **cannot** be boot volumes. Pair: gp2 boot + st1 data.
<!--SR:!2026-08-27,0,178-->

Boot volume vs data warehouse volume, cost-optimized — which combo?
?
**gp2 (boot) + st1 (data warehouse).** io1 is overkill/expensive for boot; gp2 for a warehouse wastes money.
<!--SR:!2026-08-18,2,230-->

You need shared storage that many EC2 instances access concurrently. EBS or EFS?
?
**EFS.** gp2/gp3 EBS attach to ONE instance (Multi-Attach is io1/io2 only). EFS = shared, low-latency, concurrent, scales to PB (Linux/NFS).
<!--SR:!2026-08-18,2,230-->

Transient data needing the highest possible I/O (e.g. game session data). Which storage?
?
**EC2 Instance Store** — ephemeral but fastest (physically attached). Not EFS/EBS.
<!--SR:!2026-08-19,3,250-->

On-prem Windows file servers are near capacity; add space without new hardware. What service?
?
**AWS Storage Gateway (File Gateway)** — SMB/NFS shares backed by S3. (FSx is only reachable on-prem via VPN/Direct Connect.)
<!--SR:!2026-08-18,2,230-->

Read/write-intensive Oracle DB on EC2 needs low latency + dynamic storage. Volume type?
?
**Provisioned IOPS SSD (io1).** Not EBS Multi-Attach — that's for shared access, not single-DB throughput.
<!--SR:!2026-08-17,1,170-->

## Topic E — DR Strategies & HA

Name the 4 DR strategies from cheapest/slowest to most expensive/fastest.
?
**Backup & Restore** (RTO hrs/days) → **Pilot Light** → **Warm Standby** (RTO minutes) → **Multi-site active-active** (near-zero RTO).
<!--SR:!2026-08-17,1,178-->

DR requirement: failover in 1–2 minutes, minimal cost, no data/RPO. Which strategy?
?
**Warm Standby** — a scaled-down cluster always running, ready to scale up in minutes. Active-active is unnecessarily expensive.
<!--SR:!2026-08-25,9,250-->

Website must survive an AZ failure AND auto-scale to unpredictable traffic. Config?
?
**ELB + Auto Scaling group with minimum 2 instances** (so instances exist in ≥2 AZs). CloudFront neither scales compute nor protects from AZ failure.
<!--SR:!2026-08-18,2,230-->

## Topic F — Load Balancer Selection

Route traffic based on the browser's User-Agent (or URL path). Which LB + feature?
?
**Application Load Balancer (Layer 7)** with a **listener + header/path condition**. NLB (L4) can't read HTTP headers; GWLB is for appliances.
<!--SR:!2026-08-25,9,250-->

NLB has AZ-A=2 targets, AZ-B=3 targets. Force exactly 50% traffic to each AZ. How?
?
**Disable cross-zone load balancing.** Then each LB node serves only its local AZ (50/50). With it enabled you'd get ~40/60.
<!--SR:!2026-08-17,1,198-->

## Topic G — Messaging / Decoupling

One message must reach multiple independent consumers with no EC2-to-EC2 dependency. Pattern?
?
**SNS fanout → multiple SQS queues** (one per consumer). SWF is legacy workflow orchestration, not a fanout queue.
<!--SR:!2026-08-18,2,210-->

## Topic H — Security & Governance

Force an S3 bucket to accept HTTPS only. Exact bucket-policy construct?
?
**Explicit Deny when `aws:SecureTransport` = false.** (An "allow when true" still leaves HTTP open — you must deny HTTP.)
<!--SR:!2026-08-24,8,250-->

SSE-S3: what do you get, and what do you NOT get?
?
Get: each object encrypted with a **unique AES-256 key**, fully AWS-managed. NOT: an audit trail of key use (that's **SSE-KMS**).
<!--SR:!2026-08-17,1,158-->

Encrypted connection to AWS with no internet transit. Which combo?
?
**Direct Connect + Site-to-Site VPN over Direct Connect.** DX alone avoids the internet but is **not encrypted**; the VPN adds IPsec.
<!--SR:!2026-08-17,1,210-->

Tailored customer-managed IAM policies mapped to SSO user groups. Which mechanism?
?
**AWS Identity Center custom permission sets.** Predefined permission sets hold only a single AWS-managed policy.
<!--SR:!2026-08-17,1,190-->

Control Tower: add custom preventative + detective controls beyond guardrails. How? (two)
?
**Custom SCPs on the OU** (preventative) + **Lambda/Guard rules in AWS Config** (detective). Not IAM roles.
<!--SR:!2026-08-17,1,210-->

## Topic I — Cost, Monitoring, Migration

Track compute cost per department using your own label. Two steps?
?
**Create a user-defined cost allocation tag** + **activate it in the Billing console** (and propagate it via the ASG launch template). AWS-generated tags can't be user-named.
<!--SR:!2026-08-17,1,210-->

View Windows Performance Monitor counters centrally in CloudWatch. What's required?
?
**Install the CloudWatch agent** on each instance. Detailed monitoring only shortens the interval — it doesn't capture OS-level counters.
<!--SR:!2026-08-21,5,230-->

Query AWS Cost & Usage Reports with least effort (parquet + Athena integration on). How?
?
**Run an Athena query on the parquet CUR data.** Cost Explorer can't itemize to that account-detail level.
<!--SR:!2026-08-18,2,250-->

Migrate on-prem PostgreSQL with initial + ongoing incremental syncs. Service + target?
?
**AWS DMS**, on-prem database as **source** → **RDS** as target. Not S3 dumps, not PostgreSQL-on-EC2.
<!--SR:!2026-08-17,1,210-->

Is EC2 a managed service? Who patches the OS/DB engine?
?
**No — EC2 is not managed.** AWS has no root OS access; **you** patch the OS and DB engine. AWS owns physical + hypervisor (shared responsibility).
<!--SR:!2026-08-28,12,238-->

# Part 4 — Flashcards: PT-3 & PT-4 Weak Areas

## Topic J — IAM Roles, STS & Identity

An EC2 instance needs to call S3/Redshift. How should it get credentials?
?
**Attach an IAM role to the instance.** Never an IAM user, never access keys on the instance, never creds in a security group or bastion.
<!--SR:!2026-08-20,4,199-->

You need to grant temporary, cross-account access to AWS resources. Which service?
?
**AWS STS** — `AssumeRole` returns short-lived temporary security credentials.
<!--SR:!2026-08-17,1,172-->

Federated AWS console access where roles already live in corporate Active Directory. Roles or groups?
?
**IAM Roles** (via an identity provider / AD Connector). Federation maps identities to roles, not IAM groups.
<!--SR:!2026-08-16,0,172-->

Let apps connect to RDS with a token tied to the instance profile, no stored password. Feature?
?
**IAM Database Authentication** (MySQL/PostgreSQL) — generates a 15-minute auth token.
<!--SR:!2026-08-17,1,172-->

## Topic K — Encryption Modes

"Master keys and unencrypted data must NEVER be sent to AWS." Which S3 encryption?
?
**Client-side encryption with a client-side master key.** (Client-side with a KMS key still sends a key id; SSE anything sends data to AWS to encrypt.)
<!--SR:!2026-08-16,0,172-->

Which request header requests SSE-S3 (AES-256, S3-managed keys)?
?
**`x-amz-server-side-encryption`.** (The `x-amz-server-side-encryption-customer-*` headers are for SSE-C.)

S3 Object Lock: which mode blocks even the root user, and which retention setting = a fixed time window?
?
**Compliance mode** blocks everyone incl. root. **Retention period** = fixed time; **Legal hold** = indefinite until removed. Object Lock **requires versioning enabled**.
<!--SR:!2026-08-16,0,172-->

How do you encrypt Kubernetes secrets in an EKS cluster's etcd store?
?
**Enable secret (envelope) encryption with a KMS key on the cluster.** Not EBS volume encryption.
<!--SR:!2026-08-17,1,159-->

## Topic L — Storage Service Picker

On-prem app needs SMB access to S3 with a local cache for recent files + archive to Glacier. Service?
?
**Storage Gateway File Gateway** — SMB/NFS to S3 with local caching. (DataSync is a mover with no cache.)
<!--SR:!2026-08-17,1,139-->

Best way to do a one-time bulk migration of on-prem files to S3/EFS/FSx?
?
**AWS DataSync.** For ongoing hybrid *access* you'd use Storage Gateway instead.

Which FSx variant gives Multi-AZ, low-latency **block** storage over iSCSI?
?
**FSx for NetApp ONTAP** (supports iSCSI block + NFS/SMB, Multi-AZ). FSx for Windows = SMB; FSx for Lustre = HPC hot storage.
<!--SR:!2026-08-16,0,172-->

High-performance parallel "hot" storage for ML/HPC training + cheap cold tier?
?
**FSx for Lustre (hot) + Amazon S3 (cold)** — Lustre integrates natively with S3.

250 TB to import but the internet line is far too slow. Fastest + cheapest?
?
**AWS Data Transfer Terminal** — bring physical drives to an AWS facility for high-throughput offline upload.
<!--SR:!2026-08-17,1,159-->

## Topic M — Auto Scaling Nuance

Cheapest hands-off dynamic scaling policy?
?
**Target tracking** (keeps a metric at a target). Simple/step = alarm-driven; scheduled = predictable time-based; predictive = ML forecast.
<!--SR:!2026-08-16,0,172-->

App is slow only at the start of office hours (predictable). Which policy?
?
**Scheduled scaling** — add capacity ahead of the known time window.
<!--SR:!2026-08-17,1,172-->

Need 2 instances normally but must survive a full AZ failure. Min capacity + layout?
?
**Min 4**, deployed **2 in AZ-A + 2 in AZ-B** — so 2 remain if one AZ dies.
<!--SR:!2026-08-16,0,172-->

Default ASG cooldown period, and what does it do?
?
**300 seconds.** It prevents launching/terminating more instances until the previous scaling activity takes effect (nothing to do with "downtime").
<!--SR:!2026-08-17,1,172-->

On scale-in, which instance does the default termination policy remove first?
?
The one using the **oldest launch template/configuration** (within the AZ that has the most instances).
<!--SR:!2026-08-20,4,199-->

## Topic N — CloudFront / WAF / Shield

Grant paying members access to MANY private files without changing existing URLs?
?
**CloudFront Signed Cookies.** (Signed URLs are for individual files / when you can change the URL.)
<!--SR:!2026-08-17,1,179-->

Convert images to WebP/JPEG based on User-Agent and add a custom response header at the edge?
?
**Lambda@Edge.** A response-headers policy can only set headers, not transform content.
<!--SR:!2026-08-17,1,172-->

Which service mitigates large, sophisticated DDoS attacks (vs L7 exploit filtering)?
?
**AWS Shield Advanced** for DDoS. **AWS WAF** handles SQLi/XSS and rate-based rules (deploy WAF on CloudFront/ALB).
<!--SR:!2026-08-18,2,179-->

Distribute multi-file software updates to many global sites with low latency?
?
**CloudFront** (edge-caches repeated downloads). S3 Transfer Acceleration is for uploads to a single bucket.
<!--SR:!2026-08-18,2,179-->

## Topic O — Databases & Pipelines

Migrate a database with an initial load AND ongoing incremental sync. Service + mode?
?
**AWS DMS** with **full load + CDC** (change data capture). Target can be RDS or DynamoDB. MGN rehosts servers; SCT converts schema.
<!--SR:!2026-08-20,4,199-->

Aurora: send production traffic to high-capacity instances and reporting to low-capacity ones. How?
?
**Create custom endpoints** in the Aurora cluster. The reader endpoint only load-balances across all replicas.
<!--SR:!2026-08-17,1,159-->

What happens on RDS Multi-AZ failover, and which events trigger it?
?
The **CNAME is flipped** to the standby. Triggers: primary AZ loss, primary instance/storage failure. A **read-replica** failure does NOT trigger failover.
<!--SR:!2026-08-16,0,172-->

Lambda throwing "too many connections" against RDS/Aurora. Least-code fix?
?
**Provision an RDS Proxy** to pool and reuse connections.
<!--SR:!2026-08-16,0,172-->

Database needing global scale, low latency, and frequent schema changes?
?
**Amazon DynamoDB** (NoSQL, flexible schema). Relational schemas are too rigid.
<!--SR:!2026-08-18,2,192-->

## Topic P — Monitoring, Governance, Networking

Which EC2/OS metrics require the CloudWatch agent (not available by default)?
?
**Memory utilization, swap (SwapUtilization), and disk space used.** Detailed monitoring only shortens the interval of existing metrics.
<!--SR:!2026-08-20,4,199-->

See per-process CPU/memory on an RDS instance?
?
**Enable RDS Enhanced Monitoring** (OS-level). Plain CloudWatch RDS metrics are hypervisor-level.
<!--SR:!2026-08-18,2,192-->

Detect suspicious/unauthorized access patterns on S3 and alert?
?
**Amazon GuardDuty** (threat detection). Inspector = vulnerability assessment.
<!--SR:!2026-08-16,0,172-->

Consolidate many accounts + sign in with the corporate directory. Two services?
?
**AWS Organizations** (all features) + **IAM Identity Center with AD Connector**. Not Cognito (that's for app end-users).
<!--SR:!2026-08-17,1,159-->

Standardize baselines/guardrails for newly created accounts with least effort?
?
**AWS Control Tower Landing Zone** with pre-packaged guardrails.

Allow IPv6 outbound to the internet but block inbound-initiated connections?
?
**Egress-Only Internet Gateway** (NAT gateway is IPv4-only). Add AWS Network Firewall for inspection/filtering.
<!--SR:!2026-08-16,0,172-->

Give a load balancer a static, whitelistable IP address?
?
**Network Load Balancer with an Elastic IP.** ALB has no static IP.
<!--SR:!2026-08-18,2,179-->

Private, in-VPC access to DynamoDB/S3 without the public internet?
?
A **Gateway VPC endpoint** associated via the **route table** (S3 and DynamoDB use gateway, not interface, endpoints).

# 60-Second Cheat Sheet

| | Security Group | Network ACL |
|---|---|---|
| **State** | Stateful (return auto-allowed) | Stateless (open both directions) |
| **Rules** | Allow only | Allow **and** Deny |
| **Attaches to** | ENI / instance | Subnet |
| **Reference an SG as source?** | Yes | No (CIDR only) |
| **Evaluation order (inbound)** | Second | First |
| **Default** | Denies inbound, allows outbound | Default NACL allows all; custom denies all |
| **Use when...** | Normal allow rules, tier-to-tier by SG | Must **block/deny**, subnet-wide control |

**RDS one-liners:** Read Replica = read-only, cross-region OK, own key per region. Multi-AZ = availability only, standby idle. Offload reads w/o new DB = ElastiCache. SQL Server 2014 = no read replicas.

**Backup one-liners:** RDS automated snapshots die with the instance → keep **manual + final** snapshots + **deletion protection**. AMI ≠ EFS backup. FSx/cross-region DR w/ RPO = **AWS Backup**. Instance Store = never for backups. EBS bills while stopped. Linux EBS resizes live.
