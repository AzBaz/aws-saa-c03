**Multi AZ RDS** allows to hae multiple RDS instances, where we have primary and secondary; Both are in sync. Can re-routed any RDS instance in case of outage. 
You can read and write from only one instance at a time. 
	Highly available
	Performance improvement
		Backups are taken from secondary, prevents I/O issues on master
		Restores are taken from secondary, prevents I/O issues on master

You need subnet group to build RDS instances.

**Read Replica** can be ONLY read by the application, APP has to know how and which Read Replicas to talk to. 
	Read Replicas can be in different AZ than the primary DB instance. 

**ASYNC replication** between primary DB instance the read replicas. 

Read Replicas Advantages:
	Improve performance of read heavy database
		Direct excess read traffic to replica.
	Improve availability
		Use read repliacs if master is down (*can't write to it.*)
	Temporary analytics
		Use read replicas as temp data warehouse. For business reporting. 

Read Replicas Creation:
A snapshot of you DB is taken
	 Multi AZ: of the secondary 
		 No performance issue
	Not Multi-AZ: of the primary
		Causes performance issues -> as there is an I/O suspension.

**RDS Proxy**: Permits your applications to pool and share database connections to improve their ability to scale
	Establishes a database connection pool and reuses connections in this pool.
Prevents connection timeout/rejection issues related to:
	Oversubscribing connections 
	Creating new connections at a fast rate
Avoids the memory and CPU overhead of openeing new database connection each time.
