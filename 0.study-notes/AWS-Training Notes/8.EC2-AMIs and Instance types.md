EC2 AMI- Amazon Machine Image 
	A template that contains configuration of your instance. 
	By default you have AMI of an operating system. 
	Quick start AMIs: Amazon linux, linux red hat, ubuntu, windows, microsoft sql, mac OS etc. 
Create an AMI in Instances console. 
	Create an Image for new AMI. 
	You can also use AMIs from marketplace. PaloAlto firewalls, Cisco firewalls, routers, and etc. 
**Instance Store(Ephemeral)**- Could be used as root volume, where OS will be stored. 
**Also EBS**- hardrives could also be used as root device volume

**S3, EFS, FSX, Another EC2 instance - CANNOT be instance store**

In Instance Store, there is NO persistance of data- meaning if you terminate the server, everything is gone from that drive. 
On EBS there is persistence of data- meaning your data is preserved on the drive if server was terminated. 

Instance Store difficult to make changes, can't stop it (challenging for on-demand EC2 instance). EBS easy to make changes (can stop the server=do not pay for on demand when stopped)

With EBS you pay for the server, and for EBS storage. More costly, but also more flexible. 

Check AWS AMI Market and Community AMIs- to make sure they have what kind of root volume they have, Instance Store vs. EBS.
