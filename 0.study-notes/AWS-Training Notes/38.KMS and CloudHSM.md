When it comes to encryption we have 2 different options in AWS. They are KMS (multi-tenant) and CloudHSM (Dedicated).

**KMS**- Centrally managed service to Create and Control encryption keys
Integrated with EBS, S3, Redshift, DynamoDB, EFS and more
Logs of key usage provide with CloudTrail, to meet your regulatory and compliance needs. 
Types of Keys:
	*AWS Managed CMKs* - Keys created by default when you access  service and enable encryption
	Permissions can NOT be modified
	Keys can't be shared
	*Customer Managed CMKs*- Keys that are manually created by you. 
	Permissions can be modified for better control
	Keys can be shared
	Can be multi regional

Overall KMS Features:
- Create symmetric, asymmetric, and HMAC keys where the key material is only ever used within service. 
- Create symmetric keys where the key material is generated and used within a custom key store under your control and backed by either AWS Cloud HSM or your own external key manager outside of AWS. 
- Import your own symmetric key material for use withing the service
- Define which AWS IAM users and roles can manage keys. 
- Define which IAM users and roles can use keys to encrypt and decrypt data
- Chose to have keys that were generated by the service to be automatically rotated on an annual basis.
- Temporarily disable keys so they cannot be used by anyone
- Re-Enable disabled keys
- Schedule the deletion of keys that you no longer use. 
- Audit use of keys by inspecting logs in AWS CloudTrail. 

When can you encrypt?
- when creating a drive
- EBS, EFS, RDS, DynamoDB, Redshift - must be done when building the resource
- S3 - Can be done anytime. 

**CloudHSM**- Dedicated Hardware Security Module (HSM)
Designed and validated to government standards. Tamper resistant hardware  device
Securely generate, store manage symmetric and asymmetric cryptographic keys
Used for: 
- Database encryptions
- DRM
- PKI
- Authentication and authorization
- Document signing
- Transaction processing and more.
