Instance Storage: **block level storage; very fast; can be accessed by EC2; on host.** 
	AKA Ephemeral Storage
	 On a shared-disk subsystem
	 Reclaimed when instance is stopped/terminated/fails
	 Best used for: **buffers, cache, scratch data, temporary non-persistent data**
	 Not supported by all instances.

EBS volume: **Block-Level storage volumes for EC2 instances**
	Independent from instance
	Attached/Mounted to instance: **appear as storage volumes in OS; Only attached to one instance (exclude NITRO instances-allows to attach EBS to multiple devices); Instance can have multiple volumes**
Volumes and Instances Must be in same AZ. 
Usually slower than instance storage. 
Located in EC2 console page. 
	![[Pasted image 20260525153536.png]]

Types of EBS volumes: SSD
	**General Purpose SSD (gp2, gp3)**: a balance of price and performance (upto 16,000 IO PS)
		Root/boot volume
		**Use Case: boot volume, small/medium size databases, virtual desktops, low latency interactive apps, dev and test environments**
	**Provisioned IOPS SSD (io1, io2)**
		Performance measured in IOPS: how fast you can read/write to/from disk 
		Designed for I/O intensive apps (upto 64,000/256,000 IOPS)
		Can be root/boot volume
		**Use Cases: I/o-critical business apps and intensive workloads that are sensitive to storage performance and consistency (SQl, NO SQL workloads) and require sustained IOPS**
All can be up to 16TB

Types of EBS volumes: HDD
	**Throughput Optimized HDD (st1)**; up to 16 TiB in size
		Can't be root/boot volume
		Great for throughput intensive workloads
	**Use Cases: streaming workloads that require fast and consistent throughput with low cost. I.E. big data, data warehouse, log processing**
	**Cold HDD (sc1);** up to 16 TiB in size
		Can't be root/boot volume
		Cheaper option but slower
		**Use Cases: large volumes of infrequently accessed data where cheap but instant access storage is needed such as a file share.** Archival solution right on the server.
	**Magnetic (standard); 1024 GiB  in size**
		Legacy drive used for root/boot volumes
		Can be root/boot volume
		Lowest cost of all the HDD options but slow; NOT recommended to use anymore. 
Performance measured in throughput- how much you can read/write on/from disk

Do NOT keep data on EBS volume that does not need to be accessed; You will keep paying for the drive. 

**EBS Encryption:** No need to build, maintain secure your own key management infrastructure. 
	AWS KMS CMK to encrypt volumes and snapshots.
Encrypts: Data at rest inside the volume
All data moving between the volume and the instance as encryption occurs on the servers
All snapshots created from the volume. 
Performance: Same IOPS performance as unencrypted volume with minor effect on latency. 

EBS Snapshot: backup of an instance at given time. Point in time. Shareable. incremental (only snapshots differences/changes.)
UnEncrypted volumes create UnEncrypted Snapshots. 

To Encrypt an UnEncrypted  instance: 1. Take a snapshot of UnEncrypted instance. 2. Create a NEW volume with UnEncrypted snapshot, and Encrypt the NEW Encrypted volume. 

You can encrypt an un-encrypted snapshot when you copy it. 
	If you share an Encrypted snapshot and to be able to share it MAKE SURE that you encrypted it with custom KMS key. Default automatic AWS managed key on Encrypted snapshots are not shareable. 
Snapshot gives you an ability to copy your volume.
	You can copy the volume or share the volume. 
	You create a snapshot to copy or share the volume. 

Backups of EBS volume: You can schedule automated snapshots based on your requirements. 

You can use AWS Backup service to back up different storages, such as EBS volumes, FSx, EFS etc. 

**EFS: Elastic File System**
	Simple and scalable File-based storage; Pay Only for what you use
	Accessed via networking; Not on the host.
Elastic: Grows and shrinks based on the storage requirements; Into the petabyte range; Data Stored across multiple AZs in Region
-For use only with OSs that support NFSv4 protocol
	Mount to instance or Multiple instances
	Using IP or DNS name of EFS volume
	Supports 1,000s of concurrent connections
	Can mount on-prem through Direct Connect, VPN, or EFS Sync.
Regional-based service

![[Pasted image 20260525220816.png]]

**EFS Storage Classes**
-Standard: Use for frequently accessed files
-Infrequent Access (IA): Use for storing long-lived, infrequently accessed files. Cheaper than Standard.

Lifecycle Management: Move your data between Standard and IA storage classes after a certain number of days. 

**EFS Encryption**
-In Transit: Enabled when you mount the file system.
-At Rest: enabled when you create the EFS file system. 


**Amazon FSx**: Simple and Scalable file storage; usually for Windows instances
	Fully managed; Pay for only what you use. 
	Elastic storage up to 65TB
	Single AZ, or Multi AZ Deployments.
	Automatically Encrypted
	Supports Active Directory (Windows)
	
For use with various OSs (SMB protocol)
	Mount to Instance or Multiple Instances
	Using name of FSx Share
	Supports 1,000s of concurrent connections
	Can mount on-prem through Direct Connect, or VPN. 

![[Pasted image 20260525224140.png]]

You get servers actually built for you on your AZ, for FSx. 

**FSx for Lustre**: Simple, Scalable, and Shared High Performance file Storage
	Fully managed; pay for what you use
	Adjustable storage based on you requirements
	up to 6TBs
	Provides sub-millisecond latencies, up to hundreds of GBps of throughput and up to millions of IOPS
	Uses Parallel file system (persistent or scratch)
For use with Linux OSs (Lustre protocol)
	mount to instance or multiple instances
	Use a Lustre open source client
	DNS name of share from FSx
	Can mount on-prem through Direct Connect, or VPN. 

**Amazon S3** (briefly): Repository for Internet data(static data: PDF, video, files.); Reliable/Fast/Inexpensive/Durable

Pay only for what you store
Data Stored multiple AZs in Region
Upload/Download files using API calls.
