**Default S3 permission**
By default S3 blocks all public access to your bucket and object )meaning not accessible via public internet)

**Granting S3 bucket permissions**

We use JSON code for Bucket policy.  
Use ACL to share bucket with another AWS accounts; public access

![[Pasted image 20260614161120.png]]

**S3 Presigned URLs**- UnBlock Public Access temporarily
Grant PUT or GET object access to others for limited time
	This allows you to share objects from bucket that is private
	Allows others to upload objects to a bucket that is private
Created programmatically using the SDKs or the CLI
	Embed it in website or app code
	Use it as is from a browser or CLI

 **S3 Encryption**-by default bucket is encrypted.
 In Transit- SSL/TLS; Encrypt before upload
 At Rest Encryption:
	 Server Side:
		 Use S3 Managed Keys (SSE-S3)
		 Use KMS managed keys (SSE-KMS)
		 Use customer provided keys (SSE-C)
	Client Side: Encrypt before upload using any tool

**S2 Versioning**-Allows to keep multiple versions of an object in a bucket
Keep multiple variants of an object in the same bucket- Preserve, Retrieve, Restore
Recover from unintended user actions and application failure
Object name must be exact same-Case Sensitive

![[Pasted image 20260616143303.png]]

**S3 MFA Delete**-Prevent accidental changes/deletes
Requires additional authentication for the following S3 operations:
	Change the versioning state of your bucket
	Permanently delete an object version
It will require you to provide two forms of authentication for the above actions
	Your security credentials
	The concatenation of valid serial number, a space, and the six-digit code display on an approved authentication device

**S3 Object Block**- Prevent an object from being deleted or overwritten 
For a fixed amount of time or indefinitely
	Helps meet regulatory requirements for write-once-read-many  (WORM) storage
Modes:
	Governance- Allows for overwriting or deleting an object version or alter its lock settings if the user has been granted special permissions for the retention period.
	Compliance- No one... not even the root user can overwrite or delete or modify an object or its lock settings for the retention period.
