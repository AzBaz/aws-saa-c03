## Amazon Kinesis
Easily collect, process, and analyze data streams in real time with minimal loss, so you can get timely insights and react quickly to new information. 
Platform for **real-time streaming data** ingestion and processing at scale. 

**Kinesis Data Streams** (exam heavy)
- Real-time ingestion of streaming data (logs, clickstreams, IoT, metrics) for **custom processing**.
- Data organized into **shards**, each shard = fixed capacity (1 MB/s in, 2 MB/s out). Scale by adding shards.
- **Retention**: default 24 hours, up to 365 days. Data can be **replayed** by multiple consumers.
- You manage capacity (provisioned) or use **On-Demand** mode (auto-scales).
- Consumers: Lambda, KCL apps, Kinesis Data Analytics, Firehose.
 *Scenario cue*: "real-time streaming with custom app processing / need to replay data" → Data Streams.

**Kinesis Data Firehose**
- **Fully managed** delivery service. Loads streaming data directly into destinations: **S3, Redshift, OpenSearch, Splunk**.
- **Near real-time** (buffers, minimum ~60 sec latency), not true real-time.
- **No shards, no capacity management**, auto-scales.
- Can **transform** data in flight (via Lambda) and **convert to Parquet/ORC**.
- **No replay** (does not store data; it delivers and forgets).
 *Scenario cue*: "easiest way to load streaming data into S3/Redshift, no admin" → Firehose.

**Kinesis Data Analytics**
- Run **SQL or Apache Flink** on streaming data in real time (aggregations, windows, filtering).
- Reads from Data Streams/Firehose, outputs to streams or destinations.
*Scenario cue*: "analyze/aggregate streaming data in real time with SQL" → Data Analytics.


**Kinesis Video Streams**
- Ingest and process **streaming video** from devices for ML/analytics/playback.

## AWS Elastic Beanstalk
**PaaS (Platform as a Service)** for deploying and scaling web apps. You upload code; AWS handles provisioning, load balancing, scaling, and health monitoring.
	Eliminates the worry surrounding the infrastructure running the applications
Service is free, but charged per resources you create

- Supports Java, .NET, Node.js, Python, Ruby, PHP, Go, Docker.
- Supports platforms as Apache, Nginx, Passenger, and IIS. 
- **You keep full control** of the underlying resources (EC2, ELB, ASG, RDS), it just automates their setup. Not a black box.
- **Free service**, you pay only for the underlying resources it creates.
- Uses **CloudFormation** under the hood to provision the environment.

**Core concepts**
- **Application**, the logical container.
- **Environment**, a running version (e.g., dev, prod). Two types:
    - **Web Server environment**, standard HTTP app behind a load balancer.
    - **Worker environment**, background/long-running jobs, pulls from an **SQS queue**.
- **Environment tiers** map to those two types above.

**Deployment policies** (exam favorite)
- **All at once**, fastest, but full downtime. Deploys to all instances simultaneously.
- **Rolling**, deploys in batches; reduced capacity during deploy, no extra cost.
- **Rolling with additional batch**, adds temp instances so full capacity is maintained; good for production.
- **Immutable**, launches a full new set of instances on a fresh ASG, safest, easiest rollback, but slower/more resources.
- **Blue/Green** (via environment swap), deploy to a new environment, then swap **CNAME**. Zero downtime, instant rollback.

**Exam cues**
- "Deploy a web app quickly without managing infrastructure, but still want access to the resources" → Elastic Beanstalk.
- "Zero downtime + easy rollback" → **Immutable** or **Blue/Green**.
- "Minimize cost during deploy, downtime acceptable" → Rolling / All at once.

**Beanstalk vs CloudFormation vs alternatives**
- **Elastic Beanstalk**: PaaS, opinionated, app-focused, quick deploy.
- **CloudFormation**: full **IaC**, define any infrastructure precisely (Beanstalk uses it internally).
- **CodeDeploy/CodePipeline**: deployment automation you wire up yourself, more control.
