**Amazon Aurora** Takes PostgreSQL and MySQL to another level when it comes to compute capacity, memory and storage capacity, provision instances or use serverless option. 

**Amazon Aurora Modes**
Engine Mode: Provisioned
	Predictable workloads
	Pick your instance type
		CPU: from 1 to 128 vCPU
		Memory: from 1 to 1024GiB
		Networking: from 1 to 59Gbps
		Cluster Storage: up to 128 TiB of autoscaling storage.
		
Serverless
	unpredictable workloads
	Scales Automatically
	No need to pick your instance type.

**Aurora Backups**: Creates a storage volume snapshot of your entire instance and database.
First snapshot is full and the rest are incremental
	Recover your database to any point in time
Stored in S3
Automatic
	During the backup window of your datbase 
	Retention Period of 1-35days
Manual
	for longer retention periods

**AWS Backup**: Fully managed service that makes it easy to centralize and automate backups
Supports Amazon RDS database engines and Aurora clusters
-Create a backup vault for RDS
-Create a backup plan
	Set an expiration/retention period for the backups
-Assign the RDS Instance to the plan. 

**Aurora Replicas**
Use up to 15 replicas
	You use Aurora Replicas to offload read workloads from the primary DB instance.
The primary DB instance supports read and write operations
	Performs all data modifications to the cluster volume
Aurora Replicas connect to the same storage volume as the primary DB instance
	Support read operations only. 
*Provision Replicas*
	Manually
	Autoscaling

**Aurora Considerations**
If you are having write issues:
	Change the Primary instance type
	Or use Serverless Aurora
If you are having read issues:
	Add Aurora Replica manually
	Or use Aurora Autoscaling

**Aurora Cloning**: Creates new clusters from an existing cluster
	Clone initially shares the same data pages as the original
	Clone is a seperate and independent volume

**RDS Proxy**: Permits your applications to pool and share database connections to improve their ability to scale
	Establishes a database connection pool and reuses connections in this pool
Prevents connection timeout/rejection issues related to:
	Oversubscribing connections
	Creating new connections at a fast rate
Avoids the memory and CPU overhead  of opening new database connection each time

**Aurora Global Database**: A DB cluster that spans multiple AWS Regions. 
Provides:
	Low latency global reads
	Disaster recover for regions
