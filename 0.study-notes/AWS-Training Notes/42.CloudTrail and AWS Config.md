**CloudTrail** - Records API activity made on your account. Provides visibility into user activity.
Helps with:
	Tracking changes to resources
	Tracking user activity
	Demonstrating compliance
	Troubleshooting
	Security analysis
![[Pasted image 20260708131641.png]]


*By DEFAULT CloudTrail will keep Event History* for 90 days. 
For detailed info and auditing purposes, you need create a Trail.
*Trails logged in S3 bucket*

**Best Practices**
- You MUST encrypt the logs for history of API class. 
- Log file *Validation* - must be enables to ensure the log files is correct and not altered/deleted, after CloudTrail delivered it. 

*Different* types of trails from *Different* regions can be stored in one bucket
- All regions (Console or CLI)- The same trail is created in each region automatically
- Log Files recorded in all regions to any S3 bucket in any region
- Only option for console. 
*Single Region (CLI)*
- A single trail is created in a single region
- Log files recorded in that region only to any S3 bucket in any region
- Default for CLI

**AWS Config** - Fully managed service (regional), that monitors and records configurations
Assess, Audit, Evaluate configurations of your AWS resources
Provides:
- Resource Inventory
- Configuration history
- Configuration change notification (using SNS)
Simplifies:
- Compliance Auditing
- Security Analysis
- Change management
- Operational troubleshooting. 

*How AWS Config Works* - Once enabled, it discovers all supported AWS resources
- Generates an initial CI (Configuration Item) for each resource in S3. Historical record kept from that point onwards in S3. 
- A CI will be generated each time a resource changes. Immediately and periodically
- AWS Config rules used to evaluate resources. 
	- If resources in violation- AWS Config flags and sends a notification using SNS.
