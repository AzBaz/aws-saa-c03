 [[0. AWS-SAA-Training Overview]]  

**CloudFront**- Global AWS CDN
Cache content in Edge Locations
	Reduce latency and increase performance
	When serving up content to customers globally
	Reduce overall costs
	Provide different content based on location
Improve Security
	AWS Shield (DDoS Mitigation)
	AWS WAF(Layer 7 Protection)

Some use case of CloudFront: Control media content based on region, i.e. Netflix. 
Store content at regions, and just cache the content at edge locations

*If content cached in Edge Location* it is delivered to the end user immediately
*If content not cached in Edge Location* then content is retrieved from official source/origin (EC2 or S3), content cached and delivered to user. 

**Cost Efficiency:** Caching at the edge reduces the number of requests that hit your origin, lowering both compute and data transfer costs. The recommended architectural approach for performance is _always_ to use CloudFront caching rather than replicating resources across multiple regions (which is expensive and architecturally discouraged).

**Cache Behavior & TTL:*** You can configure cache behavior, what gets cached, for how long (TTL), and rules for different URL paths. Objects can be auto-compressed to save on data transfer costs.
**Origin Shield:** An optional intermediate caching layer between edge locations and your origin that improves cache-hit ratios and reduces load on the origin.
**Viewer Protocol Policy:** You can enforce HTTPS-only, redirect HTTP to HTTPS, or allow both.

**Global Accelerator**- Sppeds up access to your content. Get to AWS architecture fasater by entering AWS network through your edge location. It is NOT caching. 
While CloudFront caches content at the edge, Global Accelerator routes _all_ traffic through AWS's private backbone network — it doesn't cache. It's more suited for dynamic content, TCP/UDP applications, gaming, IoT, or any use case where caching isn't applicable.
	Reduce latency, packet loss, jitter
	For local and global users
	Great for any content that is not static. 
	
Global Accelerator uses static IP addresses. **Supprts UDP/TCP traffic**. Supports endpoints in multiple locations.
	Global Accelerator provides two static IP addresses (anycast) that route to the nearest edge location, making it useful for scenarios where you need stable IPs (e.g., IP whitelisting).

**Health Checks & Failover:** Global Accelerator performs health checks on your endpoints and automatically reroutes traffic to healthy endpoints in other regions if one fails, supporting high availability.
