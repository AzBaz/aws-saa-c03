Scalability: Ability to increase or decrease the number of resources based on demand in an efficient and effective manner. 
	Scale out/in=More or less servers
	Scale up/down= More or less ram or storage
Availability: Ability to provide access to resources 24/7 365 days a year
	Fault tolerance
		Redundancy

**AUTO-SCALING:** Ensures you always have the correct number of instances to handle the resource demand
Launch or terminate instances based on demand ir on a schedule.
![[Pasted image 20260527101632.png]]

**Auto Scaling Components**
	Groups: EC2 servers that can be used for scaling
		Min- Minimum number of instances that must be running all the time
		Desired- Number of instances that are needed at this moment in time to meet the needs
		 Max- Maximum number of instances that can ever exist as part of the group. 
	Launch Templates: Params used when launching an instance
		AMI ID, instance type, key pair, sec. groups, and block device mapping, user data, etc. 
	Scaling Plans: Defines how and when scaling takes place
		Maintain, Manual, Scheduled, Demand, Predictive.


![[Pasted image 20260527102135.png]]

**Scaling Options**
Maintain current instance levels at all times. (Steady State): Set min/max/desired to same value
*Manual scaling*: Adjust min/max/desired value manually.
*Scheduled:* Set a time and date for scaling to occur.
*Predictive:* increase number of instances in group in advance of daily and weekly patterns in traffic flows. 
*Based on demand (Dynamic scaling):* Auto adjust based on level of resource utilization. 

**Instance health with Auto Scaling**
Health state of an instance is monitored by Auto Scaling
	Any instance that is marked as Unhealthy will be terminated and replaced.
	Any instance that exceeds a threshold will cause a scale up/down event
Determining health state
	bC default Amazon EC2 instance status checks are used. 
	If group is behind ELB, Amazon EC2 instance status checks OR ELB instance checks are used. 
	Amazon CloudWatch can be used to identify when threshold is reached. 

**Aplication Auto Scaling**
Application Auto Scaling allows to configure automatic scaling for the following resources:
	AppStream 2.0 fleets
	Aurora replicas
	Amazon Comprehend document classification and entity recognizer endpoints
	DynamoDB tables and global secondary indexes
	Amazon Elastic Container Service (ECS) Services
	ElastiCache for Redis clusters (replication groups)
	Amazon EMR clusters
	Amazon Keyspaces (for Apache Cassandra) tables
	Lambda function provisioned concurrency
	Amazon Managed Streaming for Apache Kafka (MSK) broker storage
	Amazon Neptune clusters
	SageMaker endpoint variants
	Custom resources provided by your own apps or services.
