 [[0. AWS-SAA-Training Overview]]  [[34.IAM- Users, Groups and Roles]]

**IAM Permissions**- Specify who has access to AWS resources, and what actions they can perform on those resources. 
*IAM Users, IAM Groups, IAM Roles* need permissions assigned. Else DENIED by default. 
Use principle of least privilege (Only grant a user the exact permissions they need)

*Permissions Types*
Identity Based, Created in IAM. 
	Apply to an: IAM User, Group, Role
Resource Based- Created on Resources
	Apply to a resource: S3, Glacier Vaults, SNS topics, SQS queues, KMS keys.

**IAM Policies** are created in JSON format. 
Statements of Permissions (each statements has these elements below):
	Actions: What can be done
	Resources: On what the action can be done
	Effect: Allow or Deny
	Conditions: if Needed

 **Types of IAM Policies**
 Managed (One to Many)- Standalone policies you attach to Users, Groups, and Roles
	 AWS Managed Policies- Created by AWS
	 Customer Managed Policies- Created by You.
Inline (One to One)- Created by your and embedded in a single User, Group, or Role. 
	Policy is part of the entity is is attached to. 
	Is NOT shown in Managed Policies. 

**IAM Policy Evaluation Logic**
Default Deny: Requests are denied by default. 
Explicitly Allow: Overrides the default deny and grants access
Explicit Deny: Overrides any Explicit Allows and CANNOT be overwritten.
	Does NOT matter if you had explicit Allow in other permissions, Once DENY, it overrides allow policies.
